## 흐름 (`bcppo.py` 모드)
1. `expert` 선생님: PPO + shield **on** + 선생님 규칙. 규칙은 모델 명령보다 느리게만 바꾼다.
   - 정류장: 150 m 안에서 정류장 차로로, 1 m/s²로 정류장 끝 2 m 앞에 정지, 10초 유지. 차로를 못 옮기면 감속하며 틈을 기다림
   - 신호(2단계~): 적색·편하게 설 수 있는 황색이면 1.5 m/s²로 미리 감속해 정지선 2.5 m 앞에 확실히 정지
   - 보호구역(4단계~): 제한보다 0.6 m/s 낮게, 구역 앞에서는 1.0 m/s²로 미리 감속
   - 선생님 전용 shield: 차선변경 게이트(뒤차 1.0 s, 접근 2.0 s, 교차로 앞뒤 20 m 금지), 차량 shield(앞차 4.5 m/s² 급정거 가정)
2. `collect` 시범: 정답 = shield·규칙이 고친 뒤 **실제로 적용된** 행동. 충돌·위반 판은 BC에서 뺀다
3. `bc`: 같은 HybridActorCritic으로 흉내 (가감속 정규분포 −log p, 차선 cross-entropy, 감속 정답 가중치 `--brake-weight`)
4. `dagger`: 학생이 운전하고 매 step 선생님 정답을 붙인다 → 모은 데이터 전부로 `bc` 재학습
5. `finetune` (선택): 학생 PPO + λ·BC 손실, 가치 신경망 분리, KL 조기 종료
6. `eval`: 개발 판 평가

한 단계 전체 자동 실행: `models/bc_ppo/run_stage_dagger.sh <단계> <선생님.pt> <앞 단계 학생.pt> [DAgger 회수=3] [감속 가중치=10]`
(환경변수 `TAG` 파일 접두사, `LANE` 차선 가중치, `BCPPO_LC_GATE` 선생님 게이트)

3단계 재현: `TAG=s3g LANE=10 BCPPO_LC_GATE='{"rear_tau": 3.0, "approach_horizon": 4.0, "min_rear_gap": 8.0}' models/bc_ppo/run_stage_dagger.sh 3 models/bc_ppo/teachers/s3_teacher.pt models/bc_ppo/s2_student.pt 0 10` → `runs/s3g_bc0/bc.pt`

4단계 재현: `TAG=s4y LANE=3 BCPPO_YELLOW_DECEL=2.4 BCPPO_LC_GATE='{"rear_tau": 3.0, "approach_horizon": 4.0, "min_rear_gap": 8.0}' models/bc_ppo/run_stage_dagger.sh 4 models/bc_ppo/teachers/s4_teacher.pt models/bc_ppo/s3_student.pt 0 10` → `runs/s4y_bc0/bc.pt`

## 겪은 문제와 해결 (발표용)
| 문제 | 원인 | 해결 |
|---|---|---|
| shield on 선생님 충돌 48~61% | 팀 게이트가 느슨 (서 있는 버스 뒤 5.4 m만 비어도 변경), 교차로 안 차를 못 봄 | 선생님 전용 게이트 강화 → 같은 판 충돌 6 → 0 |
| 선생님이 정류장에 못 섬 (5만 step 0회) | 15 m 구간에 10초 정지를 탐색으로 못 찾음, 놓침 −20 | 정류장 정차 규칙 → 5만 step에 개발 30판 100% |
| CPU 과부하 (부하 47/16코어) | PyTorch가 프로세스마다 코어 전부 사용 | 프로세스당 1 스레드 |
| BC → PPO에서 정차 붕괴 (87% → 0~5%) | 공유 trunk로 가치 오차 기울기가 정책을 망침 → 분리 후에도 속도 보상으로 추월하다 정류장 놓침 | 가치 신경망 분리·KL 제한. 그래도 불안정 → DAgger로 전환 |
| BC가 정류장 13% 놓침 | 학생 실수 상태(정류장 직전 왼쪽 차로)를 본 적 없음 | DAgger 1회 → 100% |
| 2단계 정류장 놓침 55% (선생님) | 왼쪽 차로에서 게이트가 막아 감속 없이 지나침 | 차로 밖이면 감속하며 틈 대기 |
| 2단계 BC 적색 위반 50% | 신호 shield의 "마지막 순간 급정거" 시범 + 감속 장면이 데이터의 0.4% | 선생님 신호 규칙(미리 감속) + 감속 정답 가중치 ×10 |
| 정지선 앞에서 천천히 밀려 넘어감 | 서 있는 동안 정답이 가속·최대 감속으로 섞여 평균≈0 | 정지선 2.5 m 앞에서 최대 감속 유지 |
| 선생님 추돌 5% | 팀 shield가 앞차도 버스만큼만 감속한다고 가정 | 앞차 4.5 m/s² 급정거 가정 → 40판 충돌 2 → 0 |
| 3단계 학생이 정류장 앞 차선변경 중 옆 충돌 (90판 4~9%) | 선생님이 뒤차 1초 간격의 아슬아슬한 틈에서 옮겨, 1~2 step 늦게 흉내 내면 8 m/s 합류 차와 부딪힘 | 시범용 선생님 게이트를 넉넉하게(뒤차 3초·접근 4초·최소 8 m, `BCPPO_LC_GATE`) → 선생님 성적 그대로, 학생 충돌 1.1% |
| 3단계 DAgger 회차마다 나빠짐 (충돌 10% → 53%) | 학생이 기다리는 동안 "옮겨" 정답이 몰려 차선변경을 서두르게 됨 | DAgger 없이 BC₀ 확정 (개발 30판 하나로 고르지 않고 90판으로 비교) |
| 4단계 학생 적색 위반 2~6% | 선생님이 2.0 m/s²로 못 서는 애매한 황색에는 통과 → 1~2 step 늦게 흉내 낸 학생은 적색에 들어감 | 시범용 황색 기준 2.4 m/s² (`BCPPO_YELLOW_DECEL`) → 학생 적색 0% |
| 4단계 보호구역 과속 | 선생님 PPO가 20 km/h 구역을 모름 | 보호구역 규칙 (제한 −0.6 m/s, 1.0 m/s² 미리 감속) → 선생님·학생 과속 0~1% |
| 4단계도 DAgger 2회차에 나빠짐 | 3단계와 같음: 차선변경 정답 5~18%로 몰림 | DAgger 없이 BC₀ |
| 개발 30판 100%인 모델이 검증 85% | 30판은 너무 적음 (실패 1판 = 3.3%p) | 고르기용 판을 90판으로 (학습 범위 시드 60판 추가) |
