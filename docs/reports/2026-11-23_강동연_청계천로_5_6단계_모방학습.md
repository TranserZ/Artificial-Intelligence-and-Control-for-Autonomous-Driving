## 원인: 옆 차로 관측 사각지대

- 옆 차로(±1) 관측(`SumoHighwayEnv._neighbor`)은 SUMO `getNeighbors`만 쓰고, **나란히 겹친 차(gap < 0)는 버린다**
- 6단계 3판에서 버스가 서 있는 735 step을 차선 직접 스캔과 비교: **옆 차로 앞차 79%, 뒷차 41%를 관측이 놓침** (`probe` 스크립트)
- 차선변경 게이트(`_lane_change_is_safe`)는 스캔을 함께 본다 → 선생님은 보고 학생은 못 보는 차가 생김
- DAgger 데이터 확인: 서 있고 관측상 옆 차로가 텅 빈 상태인데 선생님이 "기다려"인 step이 8,426개 (그중 81%는 그 차로 밀도 > 0, 즉 실제로 차가 있음) → **못 보는 걸 흉내 낼 수는 없어서** DAgger를 몇 번 해도 충돌이 안 줄었다

### 보강 (`models/dongyeon_bc/obsfix.py`, 실험용)

- ±1 차로는 `getNeighbors`와 차선 스캔 중 가까운 쪽, 겹친 차는 gap 0으로 보이게
- 같은 735 step 재확인: 놓친 차 583 → **0**
- 관측 차원은 그대로 (67) → 기존 모델도 그대로 불러올 수 있음

| **선생님 v5 시드 0 200k (`s6_student_v5.pt`)** | 72.2 / 7.8 / 15.6 | 74.4 / 7.8 / 10.0 | **73.3 / 7.8 / 12.8** |
| PPO만 (시드 1·2 best) | 64.4~66.7 / 8.9 / 15.6~16.7 | – | – |

- 개발 판 1등(DAgger+PPO 시드 0: 충돌 4.4%)은 **테스트 판에서 충돌 12.2%** — 후보 16개 중 같은 90판으로 고른 운이었다. 90판은 1판 = 1.1%p라 2~3%p 차이는 구분이 안 된다
- 그래서 **180판 합계로 골랐다**: `s6_student_v5.pt`는 이전과 충돌이 같고(7.8%) 완주 +1.1%p, 적색 -2.8%p. 개선 폭은 작다
- 신호 보강은 적색을 가장 줄였지만(10~12%) 충돌이 늘었다
- PPO만 이어서 하면 나빠진다 → 효과는 DAgger(학생이 간 장면의 선생님 정답)에서 나온다

## 한계 · 팀 결정 필요

1. **env 수정**: `s6_student_obsfix.pt`는 보강된 관측으로만 제대로 달린다. 공식 평가에 쓰려면 `env/sumo_env.py`의 `_neighbor` 수정이 필요 → 공용 파일이라 팀 결정. 바꾸면 1~5단계 학생도 다시 평가해야 함
1-1. 위 표처럼 기존 학생은 보강 관측에서 무너지므로, env 수정 시 **재학습**이 필요하다
2. **선생님 한계**: 6단계 선생님 자체가 62% (주교 앞 시간초과). 학생은 선생님보다 높게 나오기 어렵다
3. **주교 앞 구간**: 교차로 바로 뒤 주정차 + 촘촘한 옆 차로 대열 → 주정차 위치·확률 조정 여부 팀 결정
4. **적색 통과·충돌**: 최종 `s6_student_v5.pt`도 180판 적색 12.8%·충돌 7.8% — 충돌 5% 목표 미달. 적색은 관측에 신호 남은 시간이 없어 황색 판단이 어렵다(팀 규칙상 관측 추가 안 함). 충돌은 주교 앞(교차로 바로 뒤 주정차)이 대부분
5. 6단계 시범은 shield가 고친 step이 약 70% (5단계 약 50%) → 학생이 혼자 해내야 할 부분이 많음
