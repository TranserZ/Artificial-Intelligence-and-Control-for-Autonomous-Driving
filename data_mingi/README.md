# 5단계 수집 데이터 합본 (1·2·4번 + 3번 수집 중)

KL-PPO 5단계 모델로 모은 주행 데이터입니다. 담당 한 명이 2,000판씩 모으고, 250판씩 묶음 8개로 나눠 저장했습니다. 1·3·4번은 조민기, 2번은 강동연 님이 모았습니다.

## 담당별 시드와 episode 번호

| 담당 | 시드 | episode | 폴더 |
|---|---|---|---|
| 1번 | 5,000,000 ~ 5,001,999 | 0 ~ 1,999 | `s5_data_p1/` |
| 2번 | 5,010,000 ~ 5,011,999 | 2,000 ~ 3,999 | `s5_data_p2/` |
| 3번 | 5,020,000 ~ 5,021,999 | 4,000 ~ 5,999 | `s5_data_p3/` |
| 4번 | 5,030,000 ~ 5,031,999 | 6,000 ~ 7,999 | `s5_data_p4/` |

- 2번 원본은 브랜치 `data/s5-p2-dongyeon`의 `data_dongyeon/s5_data_p2/s5_data_p2_c{k}`입니다. 원본은 episode가 묶음마다 0~249로 시작합니다.
  - `s5_data_p2/`는 원본에서 episode 번호만 `2,000 + 250k + 원래 번호`로 바꾼 것입니다.
  - 나머지 값은 원본과 같습니다. 바꾸기 전에 묶음마다 `seed = 5,010,000 + 250k + 원래 번호`인지 확인했습니다.
- 담당 n의 묶음 k(`s5_klppo_p{n}_b{k}`)는 시드 `5,000,000 + (n-1)×10,000 + 250k`부터 250판, episode `(n-1)×2,000 + 250k`부터입니다.
- episode 번호는 담당끼리 겹치지 않도록 처음부터 위 표대로 매겼습니다. 합칠 때 다시 매길 필요가 없습니다.

## 조건

| 항목 | 값 |
|---|---|
| 모델 | `results/klppo1_s5_s0/step250k.pt` (KL-PPO, 5단계) |
| 코드 | 브랜치 `model/kl-ppo` 58ba5a8 + 이 브랜치의 `collect_pomdp_data.py` 수정 |
| 환경 변수 | `CGC_STAGE=5 OBS_SCAN=0 STOP_FIX=0 PLACE_FIX=0 CGC_THROUGH_VPH=400` |
| shield | 감시 모드 (운전은 모델 혼자) |
| 행동 | 결정적 (스크립트 기본값) |
| 실행 (1·3·4번) | Linux, SUMO 1.25.0, Python 3.12.3, torch 2.15.0 (CPU) |

2번은 `STOP_FIX`·`PLACE_FIX`·`CGC_THROUGH_VPH`를 지정하지 않았지만, 세 값의 기본값이 위와 같아서 환경 조건은 같습니다. SUMO 버전이 달라서 같은 시드라도 판이 조금 다르게 흘러갈 수 있습니다.

## 실행 명령

```bash
bash run_person.sh <담당 번호> <워커 수>     # 예: bash run_person.sh 1 6
```

`run_person.sh`는 아래 명령을 묶음 k = 0..7에 대해 차례로 실행합니다. 이미 있는 묶음은 건너뜁니다.

```bash
python collect_pomdp_data.py --model results/klppo1_s5_s0/step250k.pt --episodes 250 \
  --workers <워커 수> --seed $((5000000 + (n-1)*10000 + 250*k)) \
  --episode-offset $(((n-1)*2000 + 250*k)) --name s5_klppo_p${n}_b${k}
```

## `collect_pomdp_data.py` 수정

1. **KL-PPO 체크포인트 읽기:** `--policy ppo`일 때 `algorithms/kl_ppo.py`의 `load_eval_policy`로 읽습니다. 2번 브랜치의 수정과 같습니다.
2. **`--episode-offset` 옵션 추가:** episode 번호를 이 값부터 매깁니다. 시드는 그대로 `--seed + 0..episodes-1`입니다.

## 확인한 것 (1·2·4번 6,000판)

- 6,000판 모두 t가 0부터 끊김 없이 이어지고, 종료 표시(`terminated`/`truncated`)는 각 판의 마지막 step에만 있습니다.
- `next_observation`이 다음 step의 `observation`과 같고, 빈 값(NaN)이 없습니다.
- 표와 `npz`의 행 수가 묶음마다 같습니다. 세 담당의 표는 열 구성(167열)이 같습니다.
- 시드 6,000개가 겹치지 않고, episode와 시드가 위 표대로 맞습니다.
